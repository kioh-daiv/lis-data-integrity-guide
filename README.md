# 医療DX シリーズ — データインテグリティ観点の規制対応と技術要件

臨床検査部門システム（LIS）のクラウド化で「記録は信頼できるか」を担保するための、**データインテグリティ（DI）統制**を整理したシングルページ HTML ガイド。医療情報の **3 原則（真正性・見読性・保存性）** を国際的な **ALCOA+** で実装単位に分解し、国内（3省2GL・ER/ES 指針）と国際（21 CFR Part 11・EU GMP Annex 11・PIC/S PI 041）を架橋する。

## 公開ページ

➡ **https://kioh-daiv.github.io/lis-data-integrity-guide/**

## 設計思想

法規制の個別列挙では網羅は証明できない。本ガイドは 2 種類の証明を組み合わせる。

- **横の証明（網羅性）**：① ALCOA+ の 9 属性（DI の完全集合）× ② データライフサイクル 5 段（記録の一生の全段）の 2 軸で機械的に洗い出す。対象/対象外を明示宣言する。
- **縦の証明（深さ）**：各 ALCOA+ 属性を **満たすべき要件 → 技術要件 → AWS 実装例 → 残リスク** に分解。残リスクは「追加技術／運用／契約・SLA／受容」の 4 分類で引き取り先を明示。

## 構成

- **スコープと網羅性の根拠**（対象/対象外、2 軸の証明）
- **§1 国内外の規制が同じ 3 原則 / ALCOA+ に収束**：3省2GL・ER/ES 指針・21 CFR Part 11・EU Annex 11
- **§2 3 原則を ALCOA+ で分解**：9 属性 → 3 原則の全マッピング
- **§3 DI 要件 → 技術要件 → AWS 実装 → 残リスク**：IAM/CloudTrail/Object Lock(WORM)/QLDB/Time Sync/Glacier 等
- **§4 データライフサイクル 5 段**：生成→処理→保存→活用→保管/廃棄
- **§5 クラウド特有の論点**：責任共有モデル・ログ完全性・鍵管理・SaaS 事業者適合
- **§6 落とし穴チェックリスト**
- **出典（一次資料・公的情報）**

## 位置づけ

医療DX シリーズの「**深掘り編**」。本線 ②「法規制対応と技術要件」の真正性パートを DI として深掘りする補完編。基盤実装は ④「セキュア実装」、医療 AI 固有の DI は「AI 活用編」に接続する。

## 注意

2026 年 5 月時点の公的・公式情報に基づく一般整理。法規制・ガイドライン・版番は改定される（特に EU GMP Annex 11 は 2026 年央に改訂版公表見込み）。実際の適用は各原典・所管官庁・専門家の確認を前提とすること。
